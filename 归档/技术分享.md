# 技术分享（踩坑与经验）

> 本次开发中真实踩过的坑与沉淀的经验，按主题整理。

## 一、FastAPI / Uvicorn

1. **WebSocket 处理器参数必须标注 `WebSocket` 类型**
   - 症状：WS 握手全部 403，处理器从未执行（print 都不出现）。
   - 根因：FastAPI 依赖解析对无注解的 WS 参数在校验阶段抛异常 → uvicorn 收到 close-before-accept → 回 403。
   - 教训：`async def handler(ws: WebSocket, path: str)`，类型注解是必须的。

2. **"连接被拒绝 403" 的排查法**
   - uvicorn 对"未 accept 就 close"回 403；用 `TestClient` 进程内复现 + 逐层二分（最小可复现 app）定位，比猜快得多。

## 二、反向代理与 HTML 注入

3. **注入 HTML 时 `</script>` 顺序是致命细节**
   - 把预加载脚本插在 boot 配置脚本的 `</script>` **之前** → 浏览器把两段脚本当一段解析 → boot 损坏 → `script is not defined` → 整页白屏。
   - 教训：注入点必须以"首个 `</script>` 之后"为基准；验证必须用真实浏览器（urllib 只检查字符串存在，发现不了结构损坏）。

4. **幂等注入**：注入块带唯一标记（`<!--dsh-gw-inject-->`），已注入则跳过，防重复。

5. **与 React 抢样式 = 灾难**
   - 曾用 JS 轮询 + 内联样式强制侧栏全屏 → 与 React 状态打架：点关闭后宽度仍被内联样式锁死（391px 关不掉）。
   - 正解：**跟随 React 自己的状态属性**。DSH 侧栏展开状态在 frame 的 `data-sidebar-collapsed` 属性上，用纯 CSS `:not([data-sidebar-collapsed]) { grid-template-columns: 100vw ... }` 一行搞定，还天然无动画。

6. **DOM 层过滤脆弱，数据层过滤才稳**
   - 哈希类名（`Sxvs8a_`、`Md3f7G_`）随构建变化；折叠态、会话内容不同都会导致选择器失效。
   - 更严重的坑：**DSH 把助手正文和思考渲染在同一个容器（`Sxvs8a`）**，CSS 一刀切隐藏"思考容器"会把最终回复也隐藏（用户当场发现"最终回复刷没了"）。
   - 正解：在代理层改写接口响应（数据源头剔除），界面自然干净，且顺带减小传输体积。

## 三、数据与协议

7. **zstd 多帧拼接文件**
   - 会话文件每次追加独立压缩一帧（实测 3.9 万帧/12.9MB）。`decompress()` 只解第一帧得到 199 字节——用 `decompressobj(read_across_frames=True)`。
   - 尾段读取：切尾部字节后必须先找到帧魔数 `28 b5 2f fd` 对齐，否则首帧损坏报错。

8. **复刻 RPC 前先抓包**
   - DSH 的 API 信封很规范：`{"type":"client-request","rpcId","method","payload"}` → 响应 `{"type":"server-response","result":{...}}`。
   - 发消息 = `session.prompt`；答选择题 = `/api/respond`，且信封是 `result:{ok,value}` 包裹——写成平铺 `{ok,value}` 会被拒（`bad-response`），往返一次才改对。

9. **选择题问题只在事件流里**
   - `question/requested` 帧只在 mux WS 流出现（回放 + 实时），rpcId 是问题路由键，不进会话文件。
   - 网关常驻一条自己的 mux 连接当"监听者"，不依赖浏览器在线。

## 四、性能

10. **性能优化链路（手机流量场景）**
    - 先量化再优化：真实浏览器 + CDP 模拟 200ms/2Mbps，得到基线 7.3s。
    - gzip（-80%）→ immutable 缓存（二次 1.9s）→ 预加载（并行）→ 仪表盘预热（0.5s）。
    - 大坑：`assistant/chunk` 流式碎片 6.8 万条占历史响应绝大多数——**过滤它 = 加载速度质变**。

11. **crypto.randomUUID 需要安全上下文**
    - 局域网 HTTP 下手机浏览器没有该 API → DSH 界面崩溃。注入 polyfill（`crypto.getRandomValues` 可用）即可；走 HTTPS（Tailscale）则原生可用。

## 五、工程与运维

12. **PowerShell 编码陷阱**
    - `Get-Content | Set-Content -Encoding UTF8` 会把 UTF-8 中文按 GBK 误读再存 → 界面乱码（"监控"→"鐩戞帶"）。
    - 写含中文的脚本/文件用 UTF-8 无 BOM 直写；`.cmd` 一律纯 ASCII + `%~dp0` 相对路径（项目目录含中文时尤其重要）。

13. **静态资源版本号**：前端改完必须 `?v=` 递增，否则手机浏览器缓存旧 JS，问题"修了但没生效"。

14. **测试用真实浏览器**：playwright-core + 系统 Edge（`channel`/`executablePath` 直连，无需下载浏览器），无头验证 DOM/交互/报错，替代"猜"。

15. **安全模型认知**
    - DSH 无鉴权 + `danger-full-access`：远程 = 可执行任意命令。安全全靠登录墙（限速+审计），并选私有隧道（Tailscale tailnet only）而非公网穿透（cpolar 等）。
    - 数据层过滤是双赢：既"减少历史加载"，又"敏感内容不落手机"。

## 六、给后来者的建议

- 一切改动先在真实浏览器验证再交付（本项目 90% 的 bug 是"没进浏览器看"导致的）。
- 优先数据层/接口层方案，别跟框架的 DOM 搏斗。
- 性能优化按"先测量 → 找大头（6.8 万条 chunk）→ 对症"来，不要盲目加缓存。
